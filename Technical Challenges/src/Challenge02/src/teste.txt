# TESTE TÉCNICO #02 — Java + POO

**Nível:** iniciante avançado
**Progressão:** um degrau acima do Teste #01.

Neste teste vou mudar o problema. Quero descobrir se você consegue aplicar **construtores, sobrecarga, encapsulamento e
métodos** em uma situação diferente — sem ficar preso ao modelo de estoque.

---

## Cenário

Você está desenvolvendo um pequeno sistema de **cadastro de funcionários**.

Cada funcionário possui:

- `nome`
- `idade`
- `salario`
- `cargo`

O sistema deve permitir criar funcionários de diferentes maneiras.

### Requisito 1 — Cadastro completo

Deve ser possível criar um funcionário informando:

```text
nome
idade
salário
cargo
```

### Requisito 2 — Cadastro simplificado

Também deve ser possível criar um funcionário informando apenas:

```text
nome
cargo
```

Nesse caso:

```text
idade = 18
salário = 0
```

Você deve decidir como implementar isso utilizando **sobrecarga de construtores**.

---

## Regras de negócio

### Nome

Não pode ser vazio.

### Idade

Deve ser maior ou igual a 18.

### Salário

Não pode ser negativo.

### Cargo

Não pode ser vazio.

---

## Comportamentos

O funcionário deverá possuir métodos para:

### 1. Exibir informações

Mostrar todos os dados do funcionário.

### 2. Aumentar salário

Receber uma porcentagem de aumento.

Exemplo:

```text
Salário: 2000
Aumento: 10%

Novo salário: 2200
```

A porcentagem deve ser **maior que zero**.

### 3. Alterar cargo

Receber um novo cargo.

O novo cargo não pode ser vazio.

### 4. Verificar maioridade

Criar um método que retorne `boolean` indicando se o funcionário possui 18 anos ou mais.

---

# Requisitos técnicos

A estrutura mínima esperada é:

```text
Main
Funcionario
```

Na classe `Funcionario`, utilize adequadamente os conceitos que você já estudou:

- `private`
- getters/setters
- `this`
- construtores
- **sobrecarga de construtores**
- métodos
- parâmetros
- retorno
- `boolean`
- condicionais

### Importante

**Não precisa usar nada que você ainda não estudou.**

Não quero `ArrayList`, herança, interfaces, streams etc.

---

# Cenário mínimo de teste

Na `Main`, demonstre pelo menos:

### Funcionário 1

Criação utilizando o **construtor completo**.

### Funcionário 2

Criação utilizando o **construtor simplificado**.

Depois:

- exiba os dados;
- aplique um aumento salarial;
- altere o cargo;
- utilize o método de maioridade.

Também faça **pelo menos dois testes inválidos**, para demonstrar que suas regras de negócio realmente funcionam.

---

# O que estou avaliando neste teste

Agora vou prestar atenção especial em algo que faltou no Teste #01:

### **Você realmente entendeu construtores e sobrecarga?**

Não basta o código compilar.

Quero observar se você naturalmente consegue pensar:

```text
Funcionario
     │
     ├── construtor completo
     │
     └── construtor simplificado
```

Também vou observar se você consegue evitar colocar validações de qualquer jeito e se consegue manter a classe responsável pelo próprio estado.
